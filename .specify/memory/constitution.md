# Grovelog Constitution

## Core Principles

### I. Plant inventory comes first

The primary purpose of Grove Log is to reliably track individual plants and their care history. Anything that does not directly support inventory, reminders, or plant health is out of scope for Phase 1.

### II. Each plant is a unique entity

Every plant must have:

- Its own identity
- Its own history (watering, fertilizing, notes)
- Its own future plan

Plants are not just “instances of a species.”

### III. Reduce reliance on human memory

The app exists because human memory does not scale.
If a user must remember something important, the app has failed.

### IV. Urgent vs non-urgent communication is sacred

- Urgent, actionable risks → phone notifications (missed watering, frost risk, extreme weather)
- Advice, suggestions, optimization → inside the app only
- Never spam notifications.

### V. Security is non-negotiable

- User data must be end-to-end encrypted wherever feasible.
- The platform owner must not be able to read private plant notes, images, or plans.
- The system should minimize how much user data is stored on servers
- Authentication must be secure, even if simple
- Convenience never overrides safety.
- Community content is explicitly opt-in and public.

### VI. Offline-friendly and resilient

- The system should degrade gracefully with limited connectivity.
- Core plant data should remain accessible even if the network is unavailable.

### VII. Extensible inventory foundation

- The architecture should support future inventory types (e.g., livestock, sellable goods, e-commerce listings) without redesigning the core system.

### VIII. Weather-aware, not weather-obsessed

Weather data should:

- Improve care decisions
- Trigger warnings when relevant
- Weather should never overwhelm the user with noise.

### IX. Cross-platform, low-friction access

Phase 1 prioritizes:

- Cross-platform access (web-first acceptable)
- Simple onboarding
- Minimal setup before value is delivered
- First-time users should log plants within minutes, not hours.

### X. Ship something real

A smaller, stable system in real users’ hands beats a perfect system that never launches. Decisions should favor:

- Simplicity
- Maintainability
- Real-world usage

### XI. Accessible & Readable

Pages use semantic HTML, readable typography, and sufficient contrast. Content should be usable with keyboard navigation and screen readers.

### XII. Fast Loading

Assets are small and optimized. Avoid unnecessary scripts, fonts, or images that slow down page load.

## Governance

Constitution supersedes all other practices; Amendments require documentation, approval, migration plan
